Key findings

  • Static image mode is ~5× faster than video mode — 8.0 s vs 40.9 s average wall per run. Face detection runs once per image, not on every frame.
  • Image mode is dominated by fixed overhead. A 5 s clip takes 6.25 s, a 20 s clip 7.51 s — the model load and single face detection cost more than the extra frames.
  • Video mode runs at ~2.88× realtime on this MIG slice (40.9 s wall for a 14.2 s clip), with 18.5 GB peak VRAM.
  • Output duration matches input audio for all 12 runs (difference ≤ 0.01 s).
  • Cold start matters. The very first image run took 47.15 s; after the weights and face detector were in page cache, the same run took 9.96 s. The table uses warm runs.

Method & caveats

Commands

# image (static, 24 fps) ~/envs/latentsync/bin/python inference.py \ --checkpoint_path checkpoints/wav2lip_gan.pth \ --face .../visual_01.jpg \ --audio .../hi.wav \ --outfile .../visual01-hi.mp4 \ --static True --fps 24 # video (fps from source) ~/envs/latentsync/bin/python inference.py \ --checkpoint_path checkpoints/wav2lip_gan.pth \ --face .../marathi-demo-2.mp4 \ --audio .../hi.wav \ --outfile .../video-hi.mp4

Measurement

  • Wall time: full inference process, from spawn to exit.
  • Includes: Python startup, torch/CUDA init, checkpoint load, face detection, Wav2Lip inference, ffmpeg mux.
  • RTF: wall ÷ audio duration; 1.0 = realtime.
  • Sampling: GPU memory every 0.5 s, process-tree RSS every 0.5 s.
  • Hardware: NVIDIA RTX PRO 6000 Blackwell Server Edition MIG 1g.24gb; torch 2.7.1+cu128, CUDA 12.8, Python 3.10.13.
  • Audio: OmniVoice zero-shot, same Marathi female reference; 14.20 / 14.22 / 14.28 s for hi/en/mr.

Caveats. Static-image outputs move only the mouth; the head and background are frozen. Image resolution is native (450×678 and 554×554) and was not upscaled. The 20 s timing audio is a looped extension, not a separate script. The 64.5 s legacy run loops a 15.02 s source video. Node05's Slurm GPU detection was broken at run time, so these jobs ran manually over SSH on one MIG 1g.24gb slice; timings are not directly comparable to full-GPU or H200 runs. Per request, no LSE-D/C, CSIM or NIQE quality metrics were run for these new outputs.
